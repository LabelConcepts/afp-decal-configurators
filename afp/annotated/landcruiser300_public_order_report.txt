landcruiser300_public_order — AFP Toyota LandCruiser 300 Public Order Management
=================================================================================

IMPORTANT METHODOLOGY NOTE (read first)
----------------------------------------
The pipeline's auto-picked reference image (source_images/landcruiser300_public_order.png)
is page 1 of the source PDF ("138296 - AFP - LANDCRUISER 300 - PUBLIC ORDER - FITTING.pdf"),
which is a TEXT-ONLY part checklist with zero embedded images — there is no photo of the
vehicle on that page at all, so no tag position could ever be verified against it.

I went back to the original PDF (path from manifest.txt / afp_vehicles.json
source_pdf_path) and found the real vehicle reference photos on PAGE 2 (a 2x2 grid:
top-left = drive side, bottom-left = pass side, top-right = front, bottom-right = rear),
plus a page 5 crop labelled "DRIVE SIDE PLACEMENT / PASS SIDE PLACEMENT" that confirmed
the drive/pass side assignment. I rendered page 2 at the same ~130dpi scale used by the
pipeline and used THAT image (saved alongside the original as
source_images/landcruiser300_public_order_vehicle.png, 1521x1075px) as the actual working
source for measuring every tag position below. annotated/landcruiser300_public_order_tagged.png
is built on top of that page-2 image, not the original (photo-less) reference_image.

Note the top/bottom side photos are a mirrored digital mock-up of the same template
(not two independently-photographed sides), so "drive" vs "pass" assignment here follows
the document's own left-column/right-column convention (DRIVE listed first in the
checklist = top photo) cross-checked against the page-5 crop, not a left/right real-world
cue like a fuel-cap.

COUNT-MISMATCH FINDING
-----------------------
afp_vehicles.json flags parts_total_stated=26 vs parts_extracted_count=20. This is NOT a
text-extraction artifact — it's a real quirk of the source document, which has TWO
separate checklists on two different pages, each with its own "Total Number of Parts"
line: page 1 (standard decals) states 13, and page 3 (VC612 WHITE REFLECTIVE strip
parts) also states 13. 13+13 = 26, which matches parts_total_stated exactly. The 17
"items" I was given merge the unique line-entries from both pages (13 from page 1 + 4
line-entries from page 3, where the page-3 lines describe 2x/1x physical quantities) —
summing actual physical units from both pages' line-items gives 13 + 7 = 20, which
matches parts_extracted_count exactly. So both numbers are internally consistent; the
"mismatch" is just totals-per-page vs combined-line-item-count, not an error, and I did
not alter the given item list.

Also note: the 17-item list contains 4 CODE COLLISIONS where the same code string is
reused across the two checklist pages for a different decal (DRIVE-1, PASS-1, REAR-1,
REAR-2 each appear twice with different label text). To keep every placement
unambiguous I tagged the second occurrence of each with a "-STRIP" suffix (these are
all the page-3 reflective-strip border items). Mapping back to the original pairs:
  DRIVE-1       = "DRIVE 'PUBLIC ORDER CHECKS' (680/8519)"              (page 1)
  DRIVE-1-STRIP = "2x DRIVE 'CHECKS' TOP & BOTTOM STRIPS 23mm x 4650mm" (page 3)
  PASS-1        = "PASS 'PUBLIC ORDER CHECKS' (680/8519)"               (page 1)
  PASS-1-STRIP  = "2x PASS 'CHECKS' TOP & BOTTOM STRIPS 23mm x 4650mm"  (page 3)
  REAR-1        = "REAR 'PUBLIC ORDER CHECKS' (680/8519)"               (page 1)
  REAR-1-STRIP  = "2x REAR 'CHECKS' TOP & BOTTOM STRIPS 18mm x 1210mm"  (page 3)
  REAR-2        = "REAR 'POLICE' (680/8519)"                            (page 1)
  REAR-2-STRIP  = "REAR BOTTOM STRIP 40mm HIGH x 1620mm LENGTH"         (page 3)

All 17 items were visually located and placed — none skipped.
